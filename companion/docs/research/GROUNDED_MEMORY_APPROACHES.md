# 有来源的对话记忆：方案调研与本项目建议

调研日期：2026-11-09。范围：用户事实记忆和会话摘要的来源约束；依据为产品官方文档、项目源码和原始论文。

## 问题与目标

本项目的在线案例中，用户 ASR 文本只有“早上9点至下午5点。”；End 模型却提出 `fact_preference(key="工作时间", scope="persistent")`，`quote=null`，并在会话摘要中写下相同推断。长期记忆因“以后／一直／我喜欢”等关键词正则被拒，摘要仍写入数据库。这个正则不能判断来源是否支持主张：相同虚构事实设为 `session` 可通过；输入附加无关的“以后再聊”可使长期候选通过；明确陈述“我在广州读高中”反而被拒。项目现有 `validate_refs` 校验来源 ID 和非空 quote 是否为原文子串，尚不校验 `key/value` 或摘要是否被来源蕴含。

目标是让每个持久化的**事实主张**有可检查的用户原文依据，并使会话摘要遵循同一约束；时间词应作为内容，不应成为长期记忆资格的代理条件。仍须保留来源归属、用户隔离、过期、版本、显式纠正和边界规则等真实约束。

## 建议的最小改动

1. **统一事实入口。** End/Memory 输出每个候选的用户来源 `turn_id`、必填的短 `quote` 和一个原子主张；`quote` 必须是该用户原文的子串。模型可在上下文中消解指代，但不得把助手措辞、既有摘要或无主语的时间片段转成用户身份事实。没有足够证据时返回空候选。尽量使用现有 `EvidenceRef`、`MemoryCandidate`、Pydantic 和 SQLite 结构，避免新框架。
2. **以主张支持度取代持久化关键词。** 删除只看整条用户文本是否包含“以后／一直／我喜欢”等词的正则资格判断。`scope=persistent` 应依据事实性质和支持证据判断：明确用户背景/偏好可跨会话；某次安排或未指明对象的时间片段留在会话记录，或不抽取事实。必要的身份、来源、版本、纠正、过期和显式反馈约束继续执行。
3. **让摘要与事实同源。** 会话摘要不能作为绕开记忆拒绝的独立自由事实通道。End 可先返回“摘要片段 → 用户短原文”的关联；发布时只采用通过同一来源与支持检查的片段，或由已通过事实和直接可引用的会话事件构成摘要。无可支持内容时可用中性原文摘录，或保留空摘要。跟进任务也要检查所依据的用户原文与主张。
4. **对改写做有界语义校验。** 原文原样记录只需已有的来源与子串检查；候选新增谓词、用户属性或自由改写时，批量比较候选和摘要主张是否被对应用户原文支持。可把已有第二次 End/Memory 模型调用用作结构化 verifier，集中输出各主张的支持/不支持/不确定；超时或格式失败时舍弃不确定主张。若第一次调用已经用了修复预算，则宁可只保存原文摘录，不把未验证的改写入库。**这是本项目推导出的实现选择**，不是上述框架现成提供的完整校验。
5. **验证已知反例与正常例。** `早上9点至下午5点。` 不得产生“工作时间”事实或摘要；添加“以后再聊”仍不得改变结论；把候选 scope 改为 `session` 也不得绕过支持检查；`我在广州读高中。` 应可形成有原文依据的持久事实。另测“我以后想试试”“每次都提醒我”“我不想再聊这个”等计划、边界和跨会话意图，以及同一事实更正、ASR 断句和真实在线语音 End 链路。

## 取舍与验收

最小版本可先采用一次抽取：要求短原文 quote、限制摘要为可追溯片段，并做 deterministic 的来源/子串检查。这会显著改善 `quote=null` 和助手信息污染，但**不能单独阻止**“原文确有时间片段，主张却凭空添加‘工作’”的语义误归因。要覆盖本案，应增加共享的语义支持判断；可优先用现有的最多 2 次调用、20 秒 End/Memory 预算，不新增同步聊天延迟。第二次调用占用原本可用于 schema repair 的预算，是明确的可用性取舍；回归和在线测试应同时观察候选拒绝率、摘要有效率、延迟及超时。不要用更大的关键词列表代替支持判断。

修改抽取/End 提示词会改变项目的内容包摘要和准入证据；实施时按项目 CONTENT 流程更新对应 digest/receipt，再运行离线检查与在线模型、语音链路验收。
