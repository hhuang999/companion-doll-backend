# 记忆事实与摘要的来源处理

本次修改解决“早上9点至下午5点”被解释为用户工作时间的问题，并替换旧的长期关键词门槛。方案依据见 [成熟方案调研](research/GROUNDED_MEMORY_APPROACHES.md)，原始问题和反例见 [在线验证审计](ONLINE_VALIDATION_20261109.md)。

## 当前流程

1. End / Memory 从有限会话记录提取原子候选，给出来源 ID、事实内容和适用范围。信息不足可以不生成记忆；普通明确背景、习惯和偏好可跨会话保存，无需用户说“长期”“一直”等词。
2. 程序核对来源归属与已提供的原文片段；遗漏 quote 时，从已验证的用户来源 ID 绑定原话片段，不额外调用模型来抄写。
3. 有记忆或跟进候选时，将其转换成**完整待验证事实句**，用现有 Critic 模型进行一次批量 textual entailment 判断。保存范围和提取模型的自我解释不进入该判断；核对只看候选所引用的原始用户消息、记忆或反馈。
4. 仅 `entailed` 的候选进入已有的记忆提交过程；`contradicted` 和 `not_enough_information` 保留检查记录，不写成用户事实。来源版本、更正、用户隔离、过期及明确反馈归因仍由提交层执行。
5. 会话摘要由 `summary_evidence` 选中的用户原文摘录生成，最长150字符，不接受另一路未经校验的自由事实叙述。`claim` 标签不参与摘要正文。

来源支持与记忆分类分别处理。核对同时标注 `profile / session_context / episode / support_feedback / boundary`：当次倾听需求收窄到 session，当前困扰、具体经历和未确定计划归为 `episodic_event`。跨会话保留的事件是带记录时间的历史，不是当前个人属性；检索投影包含 `recorded_at` 和已知 `event_time`。明确学校背景和工作安排仍可正常保存为个人事实。

事件和当次需求的 value 直接使用用户原话摘录，key 使用来源轮次 ID。这样即使语义模型把问句误解为愿望、把沉默误解为同意，或推测用户“焦虑”，这些改写也不会成为事件内容。个人事实仍保留经过核对的结构化键值；自动蕴含判断并非事实正确性的保证。

支持反馈的内部 key（如 `feedback:<事件ID>`）不作为用户事实的一部分进入蕴含判断。对已被 Core 明确归因的反馈，程序依据同一用户轮次恢复事件引用、支持引用和反馈方向，避免模型漏填事件或误分 episode 后重复落库。提交层按事件 ID、支持引用和反馈方向去重；没有具体支持引用的明确反馈也去重，不同反馈事件仍分别保存。

例如，前提“早上9点至下午5点。”与假设“用户的工作时间是早上9点至下午5点。”仅时间值相同，缺少活动与归属，不构成蕴含；“我的工作时间是早上9点至下午5点。”才支持该假设。该判断与候选是否为 session / persistent 无关。

## 为什么这样组织

Mem0 的用户事实抽取、LangMem 的带上下文事实、Zep 的来源关联都支持保留可追溯的原始来源。本项目另借鉴原子事实一致性检查，将“字段看起来一致”改成“来源是否蕴含完整事实句”；这部分是结合研究形成的本项目实现，并非引入上述框架。

试验中，直接检查键值对、重复使用提取模型的解释，以及让核对同时判断保存期限，都出现过误判。最终核对输入隔离了提取解释和保存元数据，并将主张写成完整句。来源检查不把“存在引用”误当作“含义正确”，也不靠扩大关键词列表判定事实。

## 预算与状态

沿用 Memory / End 的两次调用与20秒预算；没有候选时不发起语义核对。实际有候选时通常为一次提取、一次核对，两者共享格式修复机会和 token 预算。

如果第一次输出已经消耗了修复调用，或核对出现超时、无效结果或额度不足，未核对候选不提交；有效的原文摘要仍可完成会话结束。取消、清除和版本冲突继续遵循现有控制规则。

任务结果增加 `consolidation_review`：

- `not_needed`：没有待核对候选。
- `passed`：所有候选均被来源支持。
- `filtered`：部分候选被判矛盾或证据不足。
- `unavailable`：核对未能完成，记录具体原因。

各项判定带 kind/index、verdict、memory_type 和 reason；候选顺序绑定和完整覆盖由程序检查。会话摘要完成而候选被过滤/未核对时，任务记为 partial。

## 范围与维护

`persistent` 表示跨会话保留，个人事实变化由后续更正更新，事件记录保留发生语境。当次需求由语义分类收窄范围，明确的交互边界继续遵循现有确定性控制；事实支持判断不要求用户作长期承诺。

本次没有新增框架、向量库或数据库 schema 迁移。`Consolidation` 在线输出改为 `summary_evidence`，历史角色运行 JSON 仍作为原始证据读取。自动语义判断仍可能出错，回归集同时检查错误事实被排除和正常事实可用，不能只统计拒绝数量。

修改 End / Memory 提示词会改变内容包 digest，需要按 [CONTENT](CONTENT.md) 更新受影响的验收证据和部署副本；已准备音频的文字与声音不变时可以复用缓存。
